# バックエンドのログ

アプリケーションのログは `log/slog` に統一し、CLI 起動時に JSON 形式で標準エラーへ出力する。通常の閾値は INFO。

- INFO: 公演・チケットの作成／更新／削除、参加者の追加／削除、精算状態の変更、Discord 連携完了、リマインド送信、ログイン完了、起動・停止、管理コマンドの完了。
- ERROR: RPC の内部障害・外部サービス利用不可・タイムアウト、認証処理やリマインドの失敗、Discord チャンネルの補償削除失敗、管理コマンドの失敗。
- 通常の参照成功、入力エラー、権限不足は記録しない。

状態変更の成功は DB 更新・commit 直後に記録する。レスポンス用の再取得が後から失敗した場合は、成功ログと障害ログの両方が残る。参加者追加の再実行では、実際に追加した参加者だけを記録する。参加者削除やチャンネル紐づけの `completed` は冪等な処理の完了を示し、変更件数を意味しない。

属性は内部 UUID（`event_id`、`ticket_id`、`actor_user_id`、`participant_user_id`、`user_id`）、固定の操作名・失敗段階・エラーコード、必要な状態値と件数に限定する。UUID は `internal/logging.ID` で正規化し、不正な入力は `invalid` に置き換える。名前・メール・自由入力・URL・Discord のユーザー識別子・Cookie・トークン・リクエスト全体は出力しない。エラー本文や外部コマンドの出力も、入力値や接続情報が混ざる可能性があるため転送しない。

RPC の障害はサービス境界で記録するため、Web と MCP の両方が対象になる。リマインドの `sent` は外部送信の成功を意味する。送信済みマークの保存に失敗した場合は `stage=mark`、`sent=true` の ERROR が残り、次回に重複送信される可能性がある。
